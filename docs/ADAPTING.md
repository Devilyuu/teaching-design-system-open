# 适配到你自己学校

这套系统原本是照着一所高职院校的教务口径写的。代码本身通用，但有若干处**硬编码了那所
学校材料的格式**。直接拿去跑，多半会卡在解析环节。

这份文档列出所有需要调整的地方，按「多半要改」到「大概率不用动」排序。每一节都写清了
**它假设了什么、在哪个文件、怎么判断你需不需要改**——你可以把这份文档连同报错一起丢给
Claude 或 Codex，让它替你改。文末有一段现成的提示词。

> 改之前先把测试跑通一遍（`cd apps/api && pytest`），改完再跑一遍。285 项后端测试是你
> 改坏了没有的判据。

---

## 0. 先把系统跑起来，别急着改

先用**脱敏示例模板**走通一遍流程，你才知道正常长什么样、你的材料差在哪。

```bash
cp .env.example .env
```

然后按 [`../README.md`](../README.md) 的「本地开发」跑起来。首次启动会创建管理员账号，
密码在启动日志里打印一次。

---

## 1. 能力指标与课程目标的代码格式（几乎一定要改）

**假设**：能力指标代码形如 `1-3-4`（三段数字），课程目标代码形如 `M1`。

系统最核心的一条硬规则就建立在这两个格式上：**AI 不许编造代码**。生成的每一条内容都要
挂到课程标准里真实存在的代码上，挂不上就中止生成。所以这个正则匹配不上，等于整条生成
链路都不工作。

| 文件 | 常量 | 现在的规则 |
|---|---|---|
| [`services/talent_plan_parser.py`](../apps/api/app/services/talent_plan_parser.py) | `INDICATOR_CODE_RE` | `\d+-\d+-\d+` |
| [`services/talent_plan_parser.py`](../apps/api/app/services/talent_plan_parser.py) | `GROUP_CODE_RE` | `\d+-\d+` |
| [`services/course_standard_parser.py`](../apps/api/app/services/course_standard_parser.py) | `ABILITY_CODE_RE` | `\d+-\d+-\d+` |
| [`services/course_standard_parser.py`](../apps/api/app/services/course_standard_parser.py) | `GOAL_CODE_RE` | `M\d+` |

**怎么判断要不要改**：打开你学校的人才培养方案，找到能力指标表，看代码长什么样。
如果是 `A1.2`、`KN-03` 这类，就得改。

---

## 2. 课程标准的「参考课时」写法

**假设**：学习内容表的参考课时写成 `理论/实践`，例如 `8/4`。

见 [`course_standard_parser.py`](../apps/api/app/services/course_standard_parser.py) 的
`REFERENCE_HOURS_RE`（`^(\d+)\s*/\s*(\d+)$`）。如果你们只写一个总数（`12`），要放宽这个正则，
并相应调整求和逻辑。

系统会机器校验一条约束：**学习内容表的参考课时合计 = 课程总学时**。这是模型最容易算错的
地方，别把这道闸门去掉。

---

## 3. 教案模板的识别标记（换模板就要改）

系统不靠占位符认教案模板，而是**靠表头文字认表**。两张表：

| 常量 | 现在的标记 | 认的是哪张表 |
|---|---|---|
| `INFO_MARKERS` | 本次课标题、授课学时、本次课教学目标、能力指标代码 | 「教学基本情况」表 |
| `PROCESS_MARKERS` | 教学环节、教学内容、教师活动、学生活动、对应教学目标 | 「教学过程」表 |

都在 [`services/lesson_template_filler.py`](../apps/api/app/services/lesson_template_filler.py)
开头。你们的教案表头如果叫「课题名称」而不是「本次课标题」，就把标记换掉。

认不出来时的报错是明确的：`教案模板未识别，请添加占位符或使用学校标准模板`。

**另一条出路**：模板里直接写 `{{教案正文}}` 占位符。系统优先认占位符，认到就不走表格识别
那套。代价是丢掉「按学校表格逐格填、保留原样式」的效果，导出会是一段纯文本。

---

## 4. `C00000` 红字契约（模板约定，不是代码）

模板里**深红色（`C00000`）的文字表示「这一格由 AI 生成」**，黑色部分教师自己填，生成过程
不碰。大纲模板和教案模板共用这一套约定。

导出前有一道闸门 `find_unfilled_generated_cells()`：回头比对模板和成品，**只要还有红字格
没被填上就中止导出**，不会悄悄交一份半成品给你。

做自己学校的模板时，把该由 AI 填的单元格文字设成 `C00000` 就行。颜色值写死在
`GENERATED_MARK_COLOR`，要换成别的颜色改那一处。

参考 [`../templates/README.md`](../templates/README.md) 和仓库里那份脱敏示例模板。

---

## 5. 教务课表格式

系统认两种课表，都在解析时自动判别：

**表头式**（[`schedule_parser.py`](../apps/api/app/services/schedule_parser.py)）：第一行是
周次/日期/星期/节次/课程/班级/地点这类表头。前 15 行内扫描，**至少命中 3 个字段**才认。
字段别名在 `FIELD_LABELS`，你们的表头用词不一样就往里加。

**矩阵式**（[`registrar_schedule.py`](../apps/api/app/services/registrar_schedule.py)）：星期
作列、节次作行，单元格内用 `/` 分隔：

```
课程/周次/校区地点/教师/教学班/课堂名称/教学班组成/板块等级/场地类别
```

字段位置写死在 `FIELD_COURSE, FIELD_WEEKS, FIELD_LOCATION, FIELD_TEACHER, FIELD_CLASS = 0, 1, 2, 3, 4`。
你们教务系统的字段顺序不同就改这几个下标。

**这块最容易踩坑**，因为各校教务系统导出差异极大。实在对不上，最省事的办法是自己整理一份
表头式 xlsx 导入。

## 6. 页眉标题（已改成通用，一般不用动）

教案模板首页居中标题（`××学院教案`）在复制课次区块时要跟着走。原先这里硬编码了校名，
现在改成按形状识别：

```python
PAGE_TITLE_PATTERN = re.compile(r"^.{0,30}教\s*案.{0,10}$")
```

只要你们的标题里带「教案」二字就能认出来。叫别的名字（比如「授课计划」）才需要改。

## 7. 大纲模板的章节结构

[`outline_template_filler.py`](../apps/api/app/services/outline_template_filler.py) 和
[`ai_outline_sections.py`](../apps/api/app/services/ai_outline_sections.py) 按
「一、基本信息 / 二、课程介绍 / …… / 八、学习要求和期望」这个八节结构生成。

章节顺序或标题不同，要同步改这两处。八节各自由谁来填，见
[`../templates/README.md`](../templates/README.md) 的对照表。

## 别改坏的三件事

这三条是这个系统**唯一比「直接问 AI 要一份教案」强的地方**。改功能的时候别顺手拆了：

1. **代码不许编造。** 课程目标代码和能力指标代码只能来自课程标准和人才培养方案。
   校验在 [`ai_lesson_validator.py`](../apps/api/app/services/ai_lesson_validator.py) 和
   [`source_validation.py`](../apps/api/app/services/source_validation.py)，
   对不上就中止，不做「尽力而为」的降级。

2. **事实性内容照抄，不经模型。** 大纲第五节（教材、参考书目、平台网址）和第六节
   （考核比例）**只允许从课程标准原样搬运**。模型编出来的书名和网址毫无破绽却查无此物，
   考核比例更是教务要对的账。课程标准里没有的，就写「课程标准中未提供，请教师补充」。

3. **导出前回头比对。** 红字格没填满就中止导出（第 4 节）。

## 让 Claude / Codex 帮你改

在仓库根目录开 Claude Code 或 Codex，把下面这段发给它，按你的情况替换尖括号部分：

```text
这个仓库是一套备课文档生成系统，原本适配的是另一所学校的教务格式。
请先读 docs/ADAPTING.md 和 CLAUDE.md，再帮我适配到我们学校。

我的材料放在 <你的材料目录>，包含：
- 人才培养方案：<文件名>
- 课程标准：<文件名>
- 课程实施大纲模板：<文件名>
- 教案模板：<文件名>

请按 ADAPTING.md 的顺序逐节检查：读我的实际文件，判断哪些格式假设对不上，
改代码让它们对上。改完跑 apps/api 的 pytest 确认没破坏现有测试。

ADAPTING.md 里「别改坏的三件事」是硬约束，不要为了让流程跑通而绕过校验。
遇到我的材料确实缺少某项信息，宁可报错提示我补充，也不要让模型编一个。
```

第一次跑通之后，建议把你们学校的格式差异记进 `CLAUDE.md`，后面再让 AI 改就有上下文了。

## 常见卡点

| 现象 | 多半是哪一节 |
|---|---|
| 上传人才培养方案后能力指标一条都没解析出来 | 第 1 节，代码正则 |
| 提示「课程标准引用的能力指标在人才培养方案中找不到」 | 第 1 节；两份材料的代码体系要一致 |
| `教案模板未识别，请添加占位符或使用学校标准模板` | 第 3 节 |
| 导出中止，提示还有单元格没填 | 第 4 节，这是闸门在正常工作——看提示补齐 |
| 课表导入后课次数量不对或全是空 | 第 5 节 |
| 大纲导出后有几节是空的 | 第 7 节，章节标题对不上 |
