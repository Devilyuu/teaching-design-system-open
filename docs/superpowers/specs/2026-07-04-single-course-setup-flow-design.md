# 新建课程单一资料入口设计

## 目标

彻底消除新建课程页与“课程资料”页并存的两套上传、解析和生成流程。教师创建课程后，只能在课程资料中心维护权威资料并继续生成。

## 页面流程

新建课程页只显示课程基础信息：学期、专业、课程名称、班级、任课教师、上课地点、课程总学时和每次课学时。

页面唯一主操作为“保存并继续准备资料”。成功后：

1. 创建课程并加入当前课程列表。
2. 选中新课程。
3. 进入课程工作台的“课程资料”页签。
4. 由课程资料中心加载后端准备状态。

创建失败时停留在原页，保留教师已填写信息并显示服务端错误。创建成功但准备状态加载失败时，课程本身仍然有效，教师可以从“我的课程”重新进入。

## 删除范围

从 `App` 删除仅服务于旧新建流程的内容：

- `MaterialKey`、`MaterialFiles` 和 `materials` 状态。
- 新建页中的人才培养方案、课程标准、课表和模板上传控件。
- 新建页对 `sourceReview` 的读取、传递和写入，以及旧核验面板。大纲编辑页仍可加载并使用课程依据数据作为代码选项。
- `handleReviewSources`、旧版 `handleGenerateOutline` 和 `ensureDraftTask`。
- `selectMaterial` 与 `draftTaskId`。
- 新建页四步指示器。
- 旧流程专用属性、导入和重复测试。

课程实施大纲和教案导出统一使用服务器中当前生效的 Word 模板，不再从新建页保留本地文件覆盖参数。

## 保留范围

- 课程资料页的五类资料上传与替换。
- 课程依据确认、课表候选确认和首次大纲生成。
- 已有课程的资料恢复入口。
- 后端旧接口暂不因前端清理而删除，避免影响已部署客户端；后续可单独做 API 弃用。

## 测试与验收

- 新建课程页不存在文件输入控件。
- 新建课程页不存在“解析并检查课程依据”和“AI 生成课程实施大纲”。
- 创建成功后“课程资料”页签处于选中状态。
- 课程资料页会请求新课程的 readiness 接口。
- 创建失败时输入内容不丢失。
- 已有课程的大纲、教案、课次材料与导出流程保持通过。
- 前端不存在旧草稿文件状态和旧新建页生成处理函数；大纲编辑所需的课程依据状态保留。

## 非目标

本次不增加 PDF 课表、质量评分、题库、知识图谱或新的后端模型，只完成主链路收口和死代码删除。
