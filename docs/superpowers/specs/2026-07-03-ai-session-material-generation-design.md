# AI 作业与测试生成设计

## 1. 目标

将单次课工作台中的规则化作业、测试草稿升级为真实 AI 生成，使教师能够依据当前课次的课程实施大纲和教案，生成可编辑、可保存、可导出 Word 的作业或测试。

本阶段只替换材料生成内核。现有材料列表、编辑、保存、删除和 Word 导出流程继续复用。

## 2. 核心原则

- 生成内容必须以当前课次的可信教学资料为依据。
- 课程目标代码和能力指标代码只允许继承，不允许模型新增或改写。
- AI 只生成教师可修改的草稿，不替教师定稿。
- 每次生成创建一份新材料，不覆盖教师已经编辑或保存的历史材料。
- 模型失败时明确提示并允许教师重试，不静默降级为规则草稿。
- 业务逻辑不绑定 DeepSeek 或任何具体模型名称。

## 3. 教师流程

1. 教师进入某次课工作台。
2. 选择生成作业或测试。
3. 设置难度和预计完成时间；测试额外设置题量。
4. 点击“AI 生成作业”或“AI 生成测试”。
5. 页面显示生成状态并暂时锁定重复提交。
6. 生成成功后，新材料加入列表并自动选中。
7. 教师修改内容、参考答案和评分标准后保存。
8. 教师将确认后的材料导出为 Word，用于学校教学平台或线下教学。

再次生成始终创建新材料，已有材料保持不变。

## 4. 可信生成依据

服务端为每次生成构建最小化证据包，只包含：

- 课程名称、专业、班级和当前课次。
- 当前课次的日期、教学主题、教学内容和预计时长。
- 当前课次已确认的课程目标代码。
- 当前课次已确认的能力指标代码。
- 当前课次教案中的教学目标、重点、难点、教学过程和课后任务，若教案已经存在。
- 教师选择的材料类型、难度、预计完成时间和题量。

模型不接收整份人才培养方案或整门课教案。服务端不得把未经确认的目标代码或能力代码加入证据包。

## 5. 结构化输出

### 5.1 作业

模型返回固定 JSON 对象，包含：

- `title`：作业标题。
- `content`：任务背景、任务要求和提交要求。
- `reference_answer`：参考成果要点或完成路径。
- `grading_criteria`：可执行的评分标准。
- `course_goal_codes`：课程目标代码数组。
- `ability_codes`：能力指标代码数组。

### 5.2 测试

模型返回固定 JSON 对象，包含：

- `title`：测试标题。
- `questions`：题目数组，每题包含题号、题干、分值、参考答案和评分说明。
- `course_goal_codes`：课程目标代码数组。
- `ability_codes`：能力指标代码数组。

服务端将题目数组格式化为现有材料表中的 `content`、`reference_answer` 和 `grading_criteria`，继续复用当前编辑和导出接口。

## 6. 校验规则

AI 返回结果保存前必须通过服务端校验：

- 必填字段不得为空。
- 作业必须包含任务要求、提交要求、参考成果要点和评分标准。
- 测试题目数量必须与教师设置一致。
- 每道测试题必须包含正分值、参考答案和评分说明。
- 测试总分必须等于各题分值之和。
- 返回的课程目标代码必须与证据包中的代码集合完全一致。
- 返回的能力指标代码必须与证据包中的代码集合完全一致。
- 模型不得返回证据包之外的目标代码或能力代码。

任一校验失败时，不创建 `SessionMaterial`，接口返回可理解的错误信息。

## 7. 技术边界

后端分为三个独立单元：

1. `SessionMaterialEvidence`：构建当前课次的可信证据包。
2. `SessionMaterialAiGenerator`：调用统一的结构化模型客户端。
3. `SessionMaterialValidator`：校验并格式化模型输出。

路由只负责权限校验、读取课程数据、组织上述服务和保存成功结果。现有 `SessionMaterial`、编辑接口和 Word 导出保持兼容。

材料增加 `generation_method` 字段，用于区分 `rule` 和 `ai`。教师后续编辑不改变生成方式，编辑时间继续由现有 `updated_at` 记录，本阶段不增加版本状态。

## 8. 模型可替换性

业务服务只依赖统一的 `generate_json` 能力，不直接引用模型名称或供应商 SDK。

- 当前 DeepSeek 继续通过 OpenAI 兼容的 Chat Completions 客户端调用。
- 支持 Chat Completions 的 OpenAI 模型可通过管理员配置中的接口地址、模型名和 API 密钥切换。
- Anthropic 原生 Messages API 与 Chat Completions 协议不同，后续通过独立 `AnthropicProvider` 适配器接入。
- 若使用提供 OpenAI 兼容协议的第三方网关，则无需新增业务层代码。

本阶段不同时实现多个供应商适配器，只保证生成、校验和业务保存逻辑与供应商解耦。

## 9. 页面行为

现有单次课工作台只做必要调整：

- 生成按钮改为“AI 生成作业”和“AI 生成测试”。
- 请求期间按钮显示生成状态并禁止重复点击。
- 成功后自动选中新材料，教师可立即编辑。
- 失败时保留当前选中材料和所有输入参数。
- 页面不增加聊天框、提示词编辑、多候选对比或供应商选择器。

管理员继续在现有模型配置页面维护模型。教师不接触 API 密钥和模型参数。

## 10. 异常处理

- 模型未配置或未启用：提示联系管理员完成模型配置并启用。
- 网络超时或供应商不可用：提示本次生成失败，可重新生成。
- 返回结构无效：列出缺失或格式错误的内容。
- 目标代码或能力代码不匹配：拒绝保存，并列出异常代码。
- 数据库保存失败：不覆盖已有材料，返回通用保存失败提示并记录服务端错误。

任何失败都不得创建空材料或修改历史材料。

## 11. 测试范围

后端测试覆盖：

- 作业与测试证据包只包含当前课次资料。
- 无教案时仍可依据课程实施大纲生成，并标记依据状态。
- 作业必填字段校验。
- 测试题量、分值、答案和评分说明校验。
- 课程目标和能力指标的严格集合匹配。
- 模型未启用、超时、无效 JSON 和校验失败均不保存材料。
- 教师只能为自己的课程生成材料。

前端测试覆盖：

- 生成参数正确提交。
- 生成期间状态与重复点击保护。
- 成功后新材料自动进入编辑区。
- 失败时保留已有材料和参数。
- 编辑、保存、删除和 Word 导出流程不回归。

## 12. 完成标准

- 教师能在单次课工作台使用已启用的 DeepSeek 模型生成作业和测试。
- 生成内容严格继承当前课次的课程目标和能力指标代码。
- 测试题量和分值通过服务端校验。
- 生成失败不会创建残缺材料或覆盖历史材料。
- AI 草稿可继续编辑、保存和导出 Word。
- 后端全量测试、前端全量测试和生产构建通过。

## 13. 暂不纳入

- 学生提交、在线答题和成绩管理。
- 题库、随机组卷和复杂题型比例配置。
- 一次生成多个候选版本。
- 异步生成队列和跨页面进度中心。
- 教师自定义系统提示词。
- 本阶段同时接入 Anthropic 原生 API。
