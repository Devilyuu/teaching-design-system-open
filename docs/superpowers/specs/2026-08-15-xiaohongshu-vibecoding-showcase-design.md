# 小红书 Vibe Coding 作品发布包设计

## 目标

以“高校教师、Vibe Coding 爱好者”的第一人称，分享智能备课系统这一开源作品。内容重点不是推销产品，而是说明真实备课痛点、系统能为教师减少哪些重复劳动，以及邀请同行教师试用、反馈和共建。

## 受众与传播目标

- 核心受众：高校及高职院校教师，尤其是关注 AI、教学设计和效率工具的教师。
- 次级受众：Vibe Coding 爱好者、教育技术从业者和愿意参与开源共建的开发者。
- 首要目标：让同行快速理解系统能做什么，并愿意评论或进入 GitHub 了解。
- 次要目标：形成可复用的“高校教师 Vibe Coding 作品日志”系列视觉语言。

## 内容定位

- 内容类型：真实作品展示 + 教师痛点拆解 + 开源复盘。
- 核心观点：把重复整理交给工具，把教学判断留给教师。
- 语气：真诚、轻松、克制，保留“边学边做”的过程感。
- 避免：产品发布会口吻、夸大 AI 能力、密集功能罗列和过量 Emoji。

## 视觉方向

采用用户确认的 B 方案：Notion 式高级知识卡片风。

- 画幅：1200 × 1600，3:4 竖版，共 8 页。
- 配色：米白与浅灰为底，墨黑正文，低饱和墨绿色作强调。
- 字体：清晰的中文无衬线字体；标题粗、正文短、注释克制。
- 元素：低圆角卡片、细分割线、标签、勾选符号和少量 `👩‍🏫 📚 🧩 ✍️ 🔍 💬` 图标。
- 截图：使用真实系统截图，每页最多一张主截图；通过裁切、遮挡和演示数据复核确保不暴露敏感信息。
- 节奏：封面强钩子，内页在截图页、清单页和流程页之间变化，避免 8 页使用同一构图。

## 八页内容结构

1. 封面：备课最费时间的事，我做成系统了。
2. 动机：写教案不是最麻烦的，找资料、对依据、套模板才是。
3. 原则：不让 AI 随便编，生成前先确认课程依据。
4. 课程规划：从课程标准和课表拆到整门课的每一次课。
5. 教案生成：支持整门课生成、逐课检查和单字段重写。
6. 单次课工作区：教案、作业和测试围绕同一次课组织。
7. 课后反思：把授课进度、学生掌握和调整接到下一次备课。
8. 开源邀请：GitHub 已公开脱敏版本，邀请教师试用、提 Issue 和共同适配。

## 发布文案结构

- 提供 5 个标题备选，优先使用第一人称和具体备课痛点。
- 正文控制为手机端易读的短段落，每段 1 至 3 句。
- 小图标只作为段落导航，不在每句话末尾添加表情。
- 正文依次覆盖：身份、动机、核心原则、主要功能、已知限制、开源说明和反馈邀请。
- 附话题标签、评论区引导及一条可置顶评论。

## 隐私与准确性

- 只使用仓库中的脱敏演示材料和已经生成的演示截图。
- 发布前逐张检查姓名、学校、课程、账号、密钥、路径、服务器地址及其他可识别信息。
- 不声称系统可以适配所有学校；明确说明不同学校的课标、课表和 Word 模板可能需要针对性调整。
- 不把“AI 生成”描述成自动替代教师判断；强调依据确认、人工修改和教师最终决定权。

## 交付物与验收

- 8 张可直接发布的 PNG 图卡。
- 一份包含标题、正文、标签、评论引导、置顶评论和配图顺序的 Markdown 文案。
- 图卡在手机缩略视图下标题可读，单页只表达一个重点，整体不呈现 PPT 或产品说明书感。
- 所有功能描述均可在 README、产品说明或真实截图中找到依据。
- 原始素材保留不覆盖，新版文件使用独立文件名，便于回退和对比。

## 后续作品复用

同一工作流可用于其他 Vibe Coding 作品。每次替换作品定位、目标读者、核心痛点、功能证据和脱敏截图；保留字体、色彩、页脚身份和结尾共建邀请，即可形成统一的个人作品系列。
